6.1 Sign-up, Login and Profile

Pages/signup, /login, /profile
API routes/api/profile (GET, PATCH), /api/auth/signout
Databaseusers (profile row created by a trigger)
External serviceSupabase Auth

What it does

Farmers create an account with their name, email and password, log in, and keep a profile with phone number, state, district and preferred answer language (English, Hindi, Telugu, Tamil, Kannada, Marathi, Bengali, Gujarati, Punjabi or Malayalam). The language and location are used by the AI advisor and the task planner.

Step by step

  1. Sign up: the farmer enters full name, email and a password of at least 6 characters and presses Sign up. The browser calls Supabase Auth signUp with the name attached.
  2. A database trigger (handle_new_user) automatically creates the farmer's private row in the users table.
  3. If the Supabase project requires email confirmation, the page asks the farmer to confirm by email; otherwise the dashboard opens.
  4. Log in: email and password → signInWithPassword. The session is kept in a secure cookie. If the farmer had tried to open a page before logging in, they are returned to it.
  5. Profile: the farmer edits name, phone, state, district and language and presses Save → PATCH /api/profile. Sign out calls POST /api/auth/signout.

6.2 Dashboard

Page/ (rendered on the server)
Databasefarms, crop_cycles, diagnoses, chat_sessions, users, crop_tasks
UsesField alert rules (6.11), weather radar (6.15)
External serviceNone directly (radar loads its own data)

What it does

The first screen after login. It greets the farmer by name (by Indian time), shows four tiles — Farm Health score, Active Crops, Diagnoses and AI Chats — eight quick-action buttons, the next 14 days of tasks, field-health readings (crop health NDVI, soil moisture, temperature and alert counts) for monitored farms, the five latest diagnoses, a farm summary and a live weather radar.

Step by step

  1. The server loads, at the same time: number of farms, crop cycles, last five diagnoses, number of chats, the farmer's name and monitored farms.
  2. It loads pending tasks due in the next 14 days (up to 6).
  3. It calculates the Farm Health score: 100 minus 25 for each open critical diagnosis, 15 for high, 8 for medium and 3 for low, never below 10. With no diagnoses it is 100 if there are active crops.
  4. For each monitored farm it runs the 9 alert rules on the latest scan and counts warnings and critical alerts.
  5. The page is sent to the browser already filled in; a loading placeholder shows while this happens.
src/app/(dashboard)/page.tsx — Farm Health score (excerpt)
const healthScore = (() => {
  const total = diagnoses?.length ?? 0
  if (total === 0) return activeCrops > 0 ? 100 : null
  const criticalWeight = (diagnoses ?? []).reduce((acc, d) => {
    if (d.status === 'resolved') return acc
    switch (d.severity) {
      case 'critical': return acc + 25
      case 'high':     return acc + 15
      case 'medium':   return acc + 8
      case 'low':      return acc + 3
      default:         return acc
    }
  }, 0)
  return Math.max(10, 100 - criticalWeight)
})()

6.3 AI Crop Disease Diagnosis

Page/diagnose
API routePOST /api/diagnose
Database / storagediagnoses; bucket diagnosis-images
External servicesVision AI chain: OpenRouter → Google Gemini

What it does

The farmer chooses the crop (Rice, Wheat, Tomato, Potato, Sugarcane, Cotton, Maize, Chili, Onion, Soybean, Groundnut, Mango, Banana, Grapes or Other) and uploads one to five photos. The AI returns a report with: disease name, whether the plant is diseased, confidence (0–100%), affected part, severity (low, medium, high, critical), cause, symptoms, organic treatment, chemical treatment (product, dosage, frequency), prevention tips, estimated yield loss if untreated and the number of days within which to act.

Step by step

  1. The farmer selects the crop, drags or picks photos, and presses Detect Disease.
  2. Optimising photos — each photo is shrunk in the browser to at most 1280 pixels and saved as JPEG (a 3.8 MB test photo became 440 KB). Photos are processed one at a time to save memory on low-cost phones.
  3. Uploading securely — the small photos are stored in the farmer's own private folder.
  4. AI analysis — the server checks sign-in, the limit of 10 diagnoses per 10 minutes, the 4 MB total size and cleans the crop name, then sends the photos to the vision AI chain asking for a JSON report.
  5. The report is checked field by field; if a model returns a broken report, a different model is asked.
  6. The report is saved with the name of the AI model that wrote it, and the report page opens. The screen shows a three-step progress card with a seconds counter; after 10 seconds it explains that backup models are being tried.
src/lib/upload.ts — shrinking a photo in the browser (simplified excerpt)
export async function compressImage(file: File, maxDim = 1280, quality = 0.82) {
  const bitmap = await createImageBitmap(file)
  const scale = Math.min(1, maxDim / Math.max(bitmap.width, bitmap.height))
  const w = Math.round(bitmap.width * scale)
  const h = Math.round(bitmap.height * scale)

  const canvas = document.createElement('canvas')
  canvas.width = w
  canvas.height = h
  canvas.getContext('2d')!.drawImage(bitmap, 0, 0, w, h)
  bitmap.close()

  const blob = await new Promise<Blob>((resolve, reject) =>
    canvas.toBlob((b) => (b ? resolve(b) : reject(new Error('Image encoding failed'))), 'image/jpeg', quality))
  return { blob, dataUrl: await blobToDataUrl(blob) }
}

function validateReport(value: unknown): DiagnosisReport {
  const r = value as Record<string, unknown>
  const disease_name = str(r.disease_name)
  if (!disease_name) throw new Error('missing disease_name')
  if (r.severity === undefined || r.is_diseased === undefined) throw new Error('missing severity / is_diseased')

  let confidence = Number(r.confidence_pct)
  if (confidence > 0 && confidence <= 1) confidence *= 100     // model replied 0.87 instead of 87

  return {
    disease_name,
    is_diseased: r.is_diseased === true || r.is_diseased === 'true',
    confidence_pct: clamp(confidence, 0, 100, 0),
    severity: SEVERITIES.includes(r.severity) ? r.severity : 'medium',
    // … symptoms, organic and chemical treatment, prevention, yield loss, urgency_days …
  }
}

6.4 Diagnosis History and Report

Pages/diagnose/history, /diagnose/[id], /diagnose/pending
Database / storagediagnoses; private photo bucket
FiltersCrop name, severity, status (open / resolved)
ShowsUp to 50 latest reports with a photo thumbnail

What it does

The history page lists the farmer's past diagnoses, newest first, with filters. Opening one shows the full report: severity badge, disease name, affected part, confidence bar, AI model used, estimated yield loss, act-within days, detection date, uploaded photos, root cause, symptoms, organic treatment, chemical treatment cards, prevention tips, an urgent-action banner and a responsible-AI notice.

Step by step

  1. The server loads the farmer's diagnoses (only their own, enforced by the database).
  2. Photos are stored privately, so the server creates fresh signed links valid for one hour — for the history page, all thumbnails in one request.
  3. If a report could not be saved earlier, the /diagnose/pending page shows it from the browser's memory with a "not saved" notice.
src/lib/storage.ts — signing photo links in one call (excerpt)
export async function signImageRefs(supabase: SupabaseClient, refs: (string | null | undefined)[], expiresIn = 3600) {
  const paths = Array.from(new Set(refs.filter((r): r is string => !!r && !isUrl(r))))
  const signed = new Map<string, string>()
  if (paths.length) {
    const { data } = await supabase.storage.from(DIAGNOSIS_BUCKET).createSignedUrls(paths, expiresIn)
    for (const d of data ?? []) if (d.path && d.signedUrl) signed.set(d.path, d.signedUrl)
  }
  return refs.map((r) => (!r ? null : isUrl(r) ? r : signed.get(r) ?? null))
}

6.5 Disease Heatmap

Page/diagnose/heatmap
API routeGET /api/diagnose/heatmap?days&crop&scope
DatabaseFunction disease_heatmap()
Filters7 days, 30 days, 90 days, 1 year · crop · everyone or only mine

What it does

A map of disease outbreaks reported by all farmers, so a farmer can see what is spreading nearby. Points are grouped into clusters and coloured by severity, on a street or satellite base map. Privacy is protected: no user ids are returned, and each farm's location is rounded to about 1 km.

Step by step

  1. The farmer picks a period, an optional crop and the scope.
  2. The server calls the database function disease_heatmap, which places each diagnosis at its owner's first farm, rounded to 2 decimal places (about 1 km).
  3. The server adds a small fixed offset (about ±250 m) so points from the same place do not sit exactly on top of each other.
  4. The map clusters the points; clicking one shows crop, disease, severity and date.
supabase/setup.sql — privacy-preserving heatmap function (excerpt)
create or replace function public.disease_heatmap(p_days integer default 90, p_crop text default null)
returns table (id uuid, lat double precision, lng double precision, crop_type text,
               disease_name text, severity text, status text, created_at timestamptz, is_mine boolean)
language sql stable security definer set search_path = ''
as $$
  select d.id,
         round(f.lat::numeric, 2)::double precision,      -- about 1 km
         round(f.lng::numeric, 2)::double precision,
         d.crop_type, d.disease_name, d.severity, d.status, d.created_at,
         d.user_id = (select auth.uid())
  from public.diagnoses d
  join lateral (select fa.lat, fa.lng from public.farms fa
                where fa.user_id = d.user_id and fa.lat is not null and fa.lng is not null
                order by fa.created_at limit 1) f on true
  where (select auth.uid()) is not null
    and d.created_at >= now() - make_interval(days => least(greatest(coalesce(p_days, 90), 1), 730))
  order by d.created_at desc
  limit 1000;
$$;

6.6 AI Farming Advisor (Chat)

Page/advisor
API routesPOST /api/chat, /api/chat/sessions, /api/chat/sessions/[id]/messages
Databasechat_sessions, chat_messages
External servicesText AI chain (streaming): OpenRouter → Google Gemini

What it does

A chat assistant that knows the farmer: their name, district, state, language, farms (area, soil, water source), active crops with growth stage, and latest diagnosis. Answers appear word by word, in the farmer's language, include dosage and timing for any chemical, flag urgent situations, and show which AI model wrote them. Conversations are saved and listed on the left; the first message becomes the conversation title.

Step by step

  1. The farmer presses New Chat (or opens a saved one) and types, speaks, or taps a suggested question.
  2. The server checks sign-in, the limit of 20 messages per minute and the message length (up to 4,000 characters).
  3. At the same time it loads: the conversation, its latest 20 messages, and the farmer's profile, farms, crops and latest diagnosis, and builds a personalised instruction for the AI.
  4. The question is saved and the text AI chain is asked to stream its answer. If a model fails before its first word, the next model takes over.
  5. Words appear on screen as they arrive; when the answer ends it is saved with the model name, which is shown under the answer.

6.7 Voice Input

WhereMicrophone button in the advisor
LanguagesEnglish (en-IN), Hindi (hi-IN), Telugu (te-IN)
Browser APIWeb Speech API (best in Chrome and Edge)
Saved settingChosen language remembered on the device

What it does

The farmer taps the microphone and speaks; the words appear in the message box while they speak, and they can edit before sending. A language switch under the box (EN, हिंदी, తెలుగు) selects the speech language.

Step by step

  1. The farmer picks the speech language (remembered for next time) and taps the microphone.
  2. The browser's speech recogniser listens continuously and returns partial and final text.
  3. The text is shown live in the message box, added to anything already typed.
  4. Tapping the microphone again stops listening; the farmer presses Send.
src/components/advisor/voice-input.tsx — speech recognition (simplified excerpt)
const LANG_MAP: Record<string, string> = { English: 'en-IN', Hindi: 'hi-IN', Telugu: 'te-IN' }

const r = new Ctor()                  // window.SpeechRecognition or webkitSpeechRecognition
r.continuous = true
r.interimResults = true
r.lang = (language && LANG_MAP[language]) || 'en-IN'

r.onresult = (event) => {
  let interim = ''
  for (let i = event.resultIndex; i < event.results.length; i++) {
    const res = event.results[i]
    const txt = res[0].transcript
    if (res.isFinal) finalBufRef.current += (finalBufRef.current ? ' ' : '') + txt
    else interim += txt
  }
  if (onInterim) onInterim((finalBufRef.current + ' ' + interim).trim())   // live text in the box
}
r.start()

6.8 Farms and Crop Cycles

Pages/farms, /farms/new, /farms/[id]
API routes/api/farms, /api/farms/[id], /api/farms/[id]/crops
Databasefarms, crop_cycles
External serviceNone

What it does

A farmer can register several farms with a name, area in acres, soil type (Loamy, Clay, Sandy, Black, Red, Silty, Other), water source (Canal, Borewell, Rainwater, Drip Irrigation, River, Pond, Tank, Other) and GPS latitude and longitude. On each farm they add crop cycles with crop name, variety, sowing date, expected harvest date and growth stage (seedling, vegetative, flowering, fruiting, harvest, harvested).   3. Add crop → form → POST /api/farms/[id]/crops; the stage starts as seedling and status as active.
  4. Editing a farm accepts only six fields (name, area, latitude, longitude, soil, water), so internal fields cannot be changed.

6.9 AI Task Planner

WhereUnder each crop on the farm page
API routesPOST /api/crops/[id]/tasks/generate, /api/crops/[id]/tasks, /api/tasks/[id]
Databasecrop_tasks
External servicesText AI chain (JSON answers)

What it does

For each crop, the AI writes a prioritised checklist of 4–6 tasks for the next 14 days, each with a title, a short description, a category (irrigation, fertilization, pest, weeding, monitoring, harvest, other), a priority (low, medium, high) and a due date. The plan uses the crop, variety, stage, sowing and harvest dates, soil, water source, the farmer's district and state, and is written in the farmer's language. Farmers can also add tasks by hand, tick them done or skipped, and delete them.

Step by step

  1. The farmer presses Generate with AI (adds tasks) or Regenerate (replaces pending AI tasks).
  2. The server checks the limit of 10 generations per 10 minutes, then loads the crop, its farm and the farmer's location and language.
  3. The text AI chain is asked for JSON. Every task is checked: unknown categories become "other", unknown priorities become "medium", due days are kept between 0 and 30. A broken answer is retried on a different model.
  4. Tasks are saved with real due dates and shown sorted by date.
src/lib/crop-tasks.ts — checking and cleaning the AI's tasks (simplified excerpt)
const validate = (value: unknown): GeneratedTask[] => {
  const tasks = (value as { tasks?: unknown })?.tasks
  if (!Array.isArray(tasks)) throw new Error('missing "tasks" array')
  const out: GeneratedTask[] = []
  for (const t of tasks) {
    const r = t as Record<string, unknown>
    const title = typeof r.title === 'string' ? r.title.trim().slice(0, 120) : ''
    if (!title) continue
    const category = CATS.includes(r.category) ? r.category : 'other'
    const priority = PRI.includes(r.priority) ? r.priority : 'medium'
    const rawDue = Number(r.due_offset_days)
    const due_offset_days = Number.isFinite(rawDue) ? Math.max(0, Math.min(30, Math.round(rawDue))) : 0
    out.push({ title, description: String(r.description ?? '').slice(0, 400), category, priority, due_offset_days })
  }
  if (out.length === 0) throw new Error('no valid tasks')
  return out.sort((a, b) => a.due_offset_days - b.due_offset_days).slice(0, 8)
}
