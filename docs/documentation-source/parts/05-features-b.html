6.10 Satellite Field Monitoring

WhereField monitoring panel on the farm page
API routes/api/farms/[id]/monitor (GET, POST, DELETE), /api/farms/[id]/satellite
Databasefarms (polygon id, latest scan), notifications
External serviceAgro Monitoring

What it does

Watches the farmer's exact field from space and from weather stations. One scan collects seven readings: weather now, the next two days of forecast (3-hour steps), soil moisture and soil temperature, UV index, crop health from satellite (NDVI value with the satellite and cloud cover, plus NDVI and true-colour images), heat units (growing degree days) and rainfall over the last 30 days.

Step by step

  1. Enable once: either enter a field radius (50 m to 5 km, default 300 m) for a square around the farm's location, or press Draw and tap at least 3 corners of the field on a street or satellite map (Undo, Clear, Save polygon).
  2. The server registers the field with Agro Monitoring and saves the returned polygon id and area (hectares).
  3. Each visit: if the last scan is under 10 minutes old it is shown again; otherwise, or when the farmer presses Refresh, a new scan runs.
  4. The seven readings are requested at the same time; if one fails, the others are still shown.
  5. The scan is saved on the farm, alerts are checked (6.11), and satellite images are loaded through the server so the API key stays hidden.
  6. Disable (after a confirmation) removes the polygon from Agro Monitoring and clears the saved scan.
src/app/api/farms/[id]/monitor/route.ts — seven readings in parallel (simplified excerpt)
async function scanPolygon(polyId: string) {
  const now = Math.floor(Date.now() / 1000)
  const thirtyDaysAgo = now - 30 * 86400

  // Fire all requests in parallel; tolerate individual failures
  const settled = await Promise.allSettled([
    currentWeather(polyId),
    forecastWeather(polyId),
    soil(polyId),
    uvi(polyId),
    latestNdviStats(polyId, 30),
    accumulatedTemperature(polyId, thirtyDaysAgo, now, 10),
    accumulatedPrecipitation(polyId, thirtyDaysAgo, now),
  ])
  const [weatherR, forecastR, soilR, uviR, ndviR, gddR, rainR] = settled
  const okOrNull = (r) => (r.status === 'fulfilled' ? r.value : null)

  return {
    scanned_at: new Date().toISOString(),
    weather: okOrNull(weatherR),
    forecast: okOrNull(forecastR)?.slice(0, 16) ?? null,   // next ~2 days at 3h
    soil: okOrNull(soilR),
    uvi: okOrNull(uviR),
    ndvi: okOrNull(ndviR),
    // … heat units, rainfall, and an error note for any reading that failed …
  }
}

6.12 Alert Thresholds

Page/settings/alerts (link from the bell)
API route/api/alert-preferences (GET, PUT)
Databaseusers.alert_preferences (JSON)
Used byAlert rules (6.11), dashboard (6.2)

What it does

Each farmer can set their own levels for every rule: heat critical and warning, cold critical and warning, soil moisture dry critical and warning, waterlogging warning, hot surface, UV critical and warning, wind critical and warning, rain critical and warning, and crop health (NDVI). A field left empty uses the default. Reset to defaults clears them; Save stores them and shows the time saved.

src/lib/alerts.ts — defaults merged with the farmer's values (simplified excerpt)
export const DEFAULT_ALERT_PREFS = {
  temp_high: { critical: 40, warning: 35 },
  temp_low: { critical: 2, warning: 5 },
  soil_moisture_low: { critical: 0.10, warning: 0.20 },
  soil_moisture_high: { warning: 0.45 },
  soil_surface_hot: { warning: 40 },
  uv: { critical: 11, warning: 8 },
  wind: { critical: 17, warning: 12 },
  rain_48h: { critical: 50, warning: 20 },
  ndvi: { critical: 0.2, warning: 0.4 },
}

function mergedPrefs(user?: AlertPreferences | null) {
  const out = JSON.parse(JSON.stringify(DEFAULT_ALERT_PREFS))
  if (!user) return out
  for (const k of Object.keys(out)) {
    const u = user[k]
    if (u && typeof u === 'object') Object.assign(out[k], u)     // farmer's value wins
  }
  return out
}

6.17 Community Forum

Pages/community, /community/new, /community/[id]
API routes/api/community, /api/community/[id], /api/community/[id]/replies
Databasecommunity_posts, community_replies
External servicesText AI chain; Supabase secret key (server only)

What it does

Farmers ask questions with crop tags, read others' posts (search and tag filter, newest 100, with reply counts), reply, and delete their own posts. With Ask AI ticked, "AgriDoctor AI" adds a practical answer of 4–7 bullet points. Author names come from the database, so nobody can post under another name, and ordinary users cannot create AI-labelled replies.

Step by step

  1. New post → title, question, tags, Ask AI (on by default) → POST /api/community. The database stamps the author's name.
  2. If Ask AI is on, the app posts a short reply requesting AI guidance.
  3. The server checks that the secret key is configured, that the post has fewer than 3 AI replies, and that the farmer has not asked for more than 5 AI replies in 10 minutes.
  4. The text AI chain writes the answer, which is saved with the server's secret key as "AgriDoctor AI". If the AI is skipped, the farmer sees the reason.
